# 汇报讲解单次开场设计

## 背景

AI 动态汇报的自动翻页正常。用户感知到的“重复讲解”来自口播内容：每讲解一个指标前，都会重复“本页查看某个时间段的指标，共多少个样本”一类背景句。

当前模型撰稿提示只要求每页生成 2–4 个讲解分段，没有限制分段之间的内容重复。确定性兜底撰稿器还会为每个指标主动拼接相同的数据范围与样本数开场，因此模型路径和兜底路径都会产生冗余。

## 目标行为

- 整份汇报仅在第一页第一段播报一次数据背景：“本页查看……时间段……共多少个样本。”
- 第一页其余分段直接讲指标、趋势、异常和结论。
- 第二页至动态最后一页全部直接讲指标，不再重复页面范围、证据来源或样本总数开场。
- 如果相关性可信度、样本不足或代表性判断确实依赖样本量，可以在分析结论中自然说明样本量；这不属于模板化页面开场。
- 页面可视化、证据声明和数据字段保持不变，只精简语音讲解文本。
- 页面数量仍由问题复杂度动态决定，本设计不修改播放、翻页、暂停、追问或恢复逻辑。

## 方案

采用“模型提示约束 + 内容校验 + 确定性兜底同步修改”的方案，不在播放前用正则临时删句。

### 模型撰稿

页面撰稿器根据 `outline.order` 给出不同口播规则：

- `order === 0`：第一段可以且只可以包含一次数据范围与样本数开场；后续分段必须直接进入指标分析。
- `order > 0`：所有分段必须直接进入指标分析，不得使用“本页查看/本页展示/本页覆盖……共 N 个样本”等页面介绍句。
- 同页各分段内容必须互补，分别承担指标现状、变化、风险或建议，不得重复页面背景或证据来源声明。

### 内容校验

在已有证据校验之后增加轻量口播规则：

- 识别“本页 + 查看/展示/分析/覆盖 + 时间范围 + 样本数”这一类模板化开场。
- 第一页只允许第一段命中一次；第一页后续分段和其他页面不得命中。
- 规则只限制模板化开场，不禁止“相关系数基于 31 个样本”这类具有统计解释意义的结论。
- 违规输出进入现有模型修复流程；若仍无法修复，则使用已同步精简的确定性兜底。

### 确定性兜底

兜底撰稿器继续保留日期范围、样本数和指标统计的证据绑定，但调整口播拼接：

- 第一页第一条指标的第一段使用一次 `context + central`。
- 第一页其他指标以及后续页面只使用 `central` 和 `range`，不再拼接 `context`。
- claim 与可视化仍可保存完整证据上下文，避免削弱审计能力。

## 备选方案与取舍

- 只改模型提示：不能覆盖确定性兜底，模型也可能偶尔忽略风格要求。
- 播放前正则删除：可能删掉有统计意义的样本量说明，并使字幕、语音和持久化文本不一致。

因此采用生成阶段的一致性约束，让模型文本、字幕、TTS 和恢复状态使用同一份精简口播。

## 测试设计

先增加失败测试，再修改生产代码：

- 模型提示测试：第一页允许一次开场，后续页面明确禁止模板化开场。
- 内容校验测试：第一页第一段的一次开场通过；第一页重复开场、第二页及后续页面开场均触发修复。
- 统计语义测试：“相关系数基于 31 个样本”仍可通过。
- 兜底测试：多指标第一页的全部口播只出现一次数据范围和样本总数；第二页兜底口播出现零次。
- 端到端模拟数据：第一页面保留一次开场，后续页面直接讲指标，避免测试环境继续展示旧行为。
- 运行现有页面生成、证据校验、报告生成、语音播放和构建测试，确认无回归。

## 修改范围

预计修改：

- `server/src/services/intent-first-slide-composer.ts`
- `server/src/domain/report-content-validation.ts`
- `server/src/services/report-evidence-fallback.ts`
- 对应服务端测试与 `e2e/server.ts` 模拟口播

不修改客户端讲解控制器、页面推进、TTS 音色、语音识别、唤醒词和用户当前进行中的 SSE 恢复改动。

## 验收标准

- 一份报告中模板化数据背景开场最多出现一次，且只位于第一页第一段。
- 第一页后续分段和所有后续页面直接讲指标，不重复时间范围、样本总数或证据来源套话。
- 具有分析价值的样本量说明不会被误删。
- 页面文本、字幕和合成语音保持一致。
- 新增回归测试、相关服务端测试、端到端测试和生产构建通过。

## 字幕数字完整性补充

本节扩展上述背景、测试设计、修改范围和验收标准，与“整份汇报只在第一页第一段出现一次数据背景开场”在同一轮实施。

### 根因

前端字幕 cue 切分器把所有英文句点 `.` 都视为句末，未判断句点两侧是否为数字。因此 `2.68 mg/L` 会被切成 `2.` 与 `68 mg/L`，`99.80%` 甚至会被切成多条字幕。字幕 CSS 已强制单行显示，服务端 TTS 分段器也不按英文句点切分，所以根因只位于 `narration-subtitle-cues.ts` 的显示 cue 切分规则。

### 目标与规则

- 完整数值与单位必须位于同一条 cue，例如 `2.68 mg/L`、`99.80%`、`0.42 个百分点` 和 `1,300.50 万元` 均不得拆分。
- 数值主体支持正负号、整数、小数和千位分隔符。
- 与数值相邻的百分号或单位一并作为不可拆分的测量原子；允许数字与单位之间存在空格。
- 单位覆盖报告当前使用的百分比、浓度、能耗、体积、质量、金额、评分、样本量和百分点表达，例如 `%`、`mg/L`、`kWh/m³`、`kg/d`、`m³`、`万元`、`分`、`个样本`、`个百分点`。
- 数字两侧均为数字时，中间的 `.` 是小数点而不是句末；真正作为句末的英文句点以及现有中文标点仍可正常断句。
- 长度预算落在测量原子内部时，优先从原子之前断开并把整个原子移到下一条 cue。
- 如果测量原子自身超过单行预算，则允许该条 cue 临时略长，也不拆开数字或单位。
- 所有 cue 重新拼接必须与原始讲解文本完全一致，并继续按显示单位计算播放进度。

该规则只改变前端字幕显示 cue，不修改持久化讲解文本、TTS 请求、音频同步方式或字幕 CSS。

### 方案取舍

采用“切分阶段识别测量原子”的方案。只忽略数字之间的小数点仍可能在长度预算处拆开单位；依赖 CSS 也无法修复已经在文本层分成两条的 cue。

### 补充测试

遵循测试先行：

- `2.68 mg/L` 不在小数点处分段，数值与单位位于同一条 cue。
- 格式矩阵覆盖 `99.80%`、`0.42 个百分点`、负数、千位分隔数和当前报告中的中英文复合单位。
- 预算落在测量原子内部时从原子之前断开；超长原子宁可单条略超预算也不拆分。
- 真正的英文句点和现有中文句末仍能断句。
- 空白、标点和所有字符均完整保留，cue 拼接结果与原文完全一致。

- `src/tests/narration-subtitle-cues.test.ts`
