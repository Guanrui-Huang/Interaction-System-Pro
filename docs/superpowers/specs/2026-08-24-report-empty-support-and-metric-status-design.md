# 汇报页空辅助图与指标状态布局修复设计

## 背景

渐进式报告画布为了避免生成过程中的模块跳动，把 dashboard 的辅助图区固定成两个槽位。该约束被同时应用到了已完成页面，导致只有一个辅助图时仍渲染第二个空白组件，完全没有辅助图时主图也无法回收右侧空间。数字指标卡使用固定高度，状态文字位于标题和数值之后的第三行，因此“达标”等状态会越过卡片底部并遮挡相邻内容。

## 目标

- 已完成页面只展示真实存在的图表，不渲染或保留空白辅助图组件。
- 按实际辅助图数量自动利用大屏空间，同时保持无滚动、无重叠。
- 渐进生成阶段继续使用稳定的模糊骨架，不出现模块揭示过程中的跳动。
- 指标状态在卡片内部拥有独立位置，不压缩或遮挡指标数字、单位和标签。
- 保持现有配色、字号、图标、字幕、证据区和揭示顺序不变。

## 完成态布局

### Data dashboard

- 0 个辅助图：不渲染辅助图区，主图横跨全部图表宽度。
- 1 个辅助图：主图保持左侧主区域，唯一辅助图占满右侧整列高度。
- 2 个辅助图：主图保持左侧主区域，两个辅助图在右侧上下均分。
- 超过 2 个辅助图：继续只展示排序后的前两个，沿用现有上限。
- 没有摘要指标时：不渲染空摘要条，主图区域回收其高度。

### 纯 KPI 页面

纯 `kpi-grid` 页面直接在画布可用区域内呈现指标网格，不再套入包含空摘要条和空辅助槽的 dashboard 外壳。

## 生成态布局

待完成页面继续使用固定 dashboard 模糊骨架，以保证生成期间结构稳定。真实页面数据到达后，完成态一次性采用该页实际的 0、1 或 2 个辅助图布局；后续标题、指标、主图、辅助图和证据的清晰化只改变可见度，不改变真实模块位置。

## 指标状态布局

每张摘要指标卡使用两行网格：

- 第一行左侧为图标和指标名称，右侧为状态文字。
- 第二行为数值和单位，横跨卡片宽度。
- 状态使用紧凑、单行的状态位，并限制在卡片内部。
- 不降低现有指标名称、数值和单位字号；8 指标密度规则仍通过间距和内边距适配。
- 没有状态的指标不保留空白状态元素。

## 组件边界

- `DataDashboardVisual` 根据实际 `supporting` 数量渲染真实辅助图，不创建空槽 DOM。
- `VisualRenderer` 的原子 KPI 画布不再创建空 dashboard 区域。
- `ReportPendingSlideView` 保留现有固定骨架，仅服务未完成页面。
- `ai.css` 通过 `data-support-count` 控制完成态 0、1、2 个辅助图的网格，并为指标状态提供独立网格区域。

## 测试与验收

- 组件测试验证完成态 0、1、2 个辅助图时只存在对应数量的真实组件。
- 组件测试验证纯 KPI 页面不存在空摘要条和空辅助槽。
- 样式测试验证 0 个辅助图主图全宽、1 个辅助图填满右列、2 个辅助图均分右列。
- 组件与样式测试验证指标状态位和数值位处于不同网格区域。
- 大屏回归在 1920×1080 下检查空组件消失、真实图表充分占满空间、指标状态未越界。
- 运行相关 Vitest、TypeScript 构建、Vite 构建和 mocked Playwright 回归。

## 非目标

- 不修改报告服务端协议、数据模型或指标生成逻辑。
- 不改变辅助图排序、图表配色和最多两个辅助图的限制。
- 不调整字幕、证据明细、对话区或缩略图设计。
- 不新增 1280×800 测试页面。
