# 语音唤醒液态呼吸球与自动分析 v4

## 目标

在不改变登录、仪表盘、AI 助手和报告主体功能的前提下，重做唤醒后的全局语音交互：液态呼吸球固定在页面底部中央，状态文字位于球体上方；小智回应、分析提示和报告讲解使用同一音色且不得叠音；用户说完问题后自动结束识别、立即进入交互报告页并开始分析。

## 已确认的交互边界

- 只有登录页不监听“小智小智”；登录后的总览、业务页、AI 助手和报告页均可后台监听。
- 唤醒成功时不切换到 AI 助手，只在当前页面显示轻量悬浮层。
- 悬浮层不使用深色圆角弹窗；液态呼吸球位于页面底部中央，距底部约 `40px` 并兼容 `safe-area-inset-bottom`。
- 状态文字位于液态呼吸球上方；关闭按钮属于轻量悬浮层，不形成卡片背景。
- 用户停止说话后自动提交识别。识别到最终问题时立即启动报告并切换交互报告页，不等待分析提示音播放完成。
- 文字输入保持当前行为：提交后立即进入交互报告页，不播放唤醒或分析提示音。
- 不修改本次需求以外的页面、数据、图表和报告布局。

## 已确认的根因

### 提示音回声

`useAssistantPromptPlayback.play()` 先异步调用 `stop()`，再创建播放会话。在 React 严格模式的 effect 重演中，两次 `play('wake')` 可以同时越过 `stop()`，各自创建 WebSocket 和播放器，形成同一句提示音并发播放。页面中的报告播报和全局提示音又由不同 Hook 管理，缺少跨组件的独占约束。

### 说完后不分析

当前实时识别关闭了服务端自动断句（`turn_detection: null`），只有客户端发送 `stop` 后，服务端才提交音频并返回最终文本。唤醒悬浮层没有停止按钮，也没有静音检测，因此用户停止说话不会触发 `stop`，`onFinal` 永远不会执行。

## 方案选择

采用“React WebGPU 组件 + CSS 降级 + 客户端静音检测 + 全局单音轨协调”方案。

未采用的方案：

- 纯 CSS 模拟液态球：体积小，但无法还原附件中的液态玻璃效果。
- 直接 iframe 嵌入附件 HTML：隔离简单，但生命周期、可访问性、尺寸同步和状态联动较差。
- 仅依赖云端 VAD：行为和延迟受上游接口影响，且当前识别协议明确使用客户端提交，现场可控性较低。

## 视觉设计

### 液态球

- 将附件中的 WebGPU shader、uniform 初始化和绘制循环封装为独立的 React canvas 组件。
- 球体桌面尺寸约 `200px`，窄屏约 `168px`；画布背景透明，不覆盖页面主体。
- `waking`、`hearing`、`analyzing` 三个阶段通过动画速度、亮度和形变强度表现，不改变业务状态文案。
- WebGPU 不可用、适配器创建失败、shader 编译失败或设备丢失时，自动显示同尺寸的 CSS 液态渐变球；语音功能继续工作。
- `prefers-reduced-motion: reduce` 时停止高频形变，只保留静态液态外观。

### 轻量悬浮层

- 使用 `position: fixed`、水平居中和底部安全距离，层级高于仪表盘与报告内容。
- 不渲染遮罩、不阻止当前页面操作，不使用深色卡片背景。
- 状态文字在球体上方居中显示；识别中的临时文本和分析问题限制宽度并允许换行。
- 关闭按钮靠近悬浮组右上角，具有可访问名称和清晰焦点态。

## 语音数据流

```text
后台关键词监听命中“小智小智”
  -> 暂停关键词监听
  -> 全局音频协调器终止旧提示音/报告播报
  -> 底部中央显示液态球与唤醒文案
  -> 使用统一 TTS 配置播放“诶，我在，请问有什么吩咐”
  -> 提示音播放完成后启动实时识别
  -> 检测到用户开始说话
  -> 连续静音约 1 秒，客户端发送 stop
  -> 服务端提交缓冲区并返回最终问题
  -> 立即启动报告并切换交互报告页
  -> 在全局单音轨约束下播放“好滴，现在我来分析：{问题}”
  -> 提示音结束后允许报告讲解占用音轨
  -> 音频输出结束并经过短暂保护间隔后恢复关键词监听
```

## 自动静音结束

- 在现有 AudioWorklet PCM 帧进入重采样器前计算输入能量，不保存、不上传额外音频，也不记录原始采样。
- 只有检测到有效人声后才启动静音倒计时，避免刚进入聆听状态就自动提交空音频。
- 连续静音目标值为约 `1000ms`；通过可测试配置项表达，默认值用于唤醒悬浮层，手动麦克风仍保留手动停止能力。
- 临时转写文本可作为“已经开始说话”的第二信号，降低轻声环境下能量阈值漏判的概率。
- 识别达到现有 `60s` 上限时仍按原逻辑停止；从未检测到有效语音时显示现有无语音错误，不启动报告。

## 单音轨与同音色

- 唤醒回应、分析提示和报告讲解继续使用同一服务端 DashScope TTS 配置与 `DASHSCOPE_TTS_VOICE`，默认音色保持 `longanlingxin`。
- 增加应用内全局播放协调器。每次播放获取唯一代次；新播放开始时撤销上一代，并使任何较晚恢复的旧异步调用失效。
- 严格模式重演、快速重复唤醒、页面切换和组件卸载均不得留下第二条 WebSocket、播放器或音轨。
- 提示音或报告讲解正在输出时暂停关键词监听，避免扬声器声音触发关键词模型；播放结束后自动恢复。

## 组件与职责

- `LiquidVoiceOrb`：只负责 WebGPU 初始化、帧循环、阶段参数和 CSS 降级，不直接管理识别或播放。
- `VoiceWakeOverlay`：编排唤醒回应、自动识别、分析启动与悬浮层状态。
- `useVoiceRecognition`：增加可选的自动静音结束配置；默认手动识别行为保持不变。
- 全局播放协调器：保证提示音与报告讲解互斥，并为后台唤醒监听提供“当前正在输出音频”的状态。
- `App`：继续维护登录后的唯一关键词监听和全局悬浮层；报告启动仍复用现有 `startReport`。

## 错误与降级

- WebGPU 失败只切换视觉降级，不关闭语音交互。
- TTS 失败不得阻止开始识别或启动报告；界面继续进入下一状态。
- 识别权限、网络或上游错误使用现有语音错误码，悬浮层允许用户关闭；关闭后清理麦克风、计时器、WebSocket 和音频。
- 用户主动关闭悬浮层时停止当前提示音与识别，并在清理完成后恢复后台关键词监听。

## 验收标准

1. 登录后任意非登录页说“小智小智”，当前页面底部中央出现液态球，文字在球体上方，页面不跳到 AI 助手。
2. 页面没有原深色圆角弹窗；液态球使用附件效果，WebGPU 不可用时有可用的视觉降级。
3. 一次唤醒只播放一次回应，没有重叠、回声或双 WebSocket 播放。
4. 小智回应、分析提示和报告讲解使用同一配置音色，彼此不重叠。
5. 用户开始说话并停止约 1 秒后，识别自动结束；最终文本返回后立即进入交互报告页并开始分析。
6. 分析提示音不阻塞页面跳转；报告讲解等待当前提示音释放音轨后再播放。
7. 播音期间不会被系统自身声音再次唤醒；播音结束后后台监听自动恢复。
8. 手动麦克风、文字输入、关闭弹层、登录页边界以及其他页面功能保持原行为。

## 测试策略

- 组件测试：液态球位置、文字顺序、阶段 class、WebGPU 失败降级和清理帧循环。
- Hook 测试：严格模式并发 `play()` 只保留最后一次播放；新代次撤销旧会话；卸载无残留音轨。
- 识别测试：检测到语音后连续静音触发一次 `stop`；起始静音不提交；继续说话会重置静音计时；手动模式不受影响。
- 应用测试：最终文本立即调用 `onStartReport`，不等待分析提示完成；文字输入仍不请求提示音。
- 集成测试：关键词命中、唤醒回应、自动停止、最终转写、报告跳转和监听恢复形成完整闭环。
- 浏览器验证：在本地 Edge/Chrome 检查实际麦克风权限、底部中央布局、无回声、自动断句、页面跳转和 WebGPU/CSS 两种渲染路径。
