# 汇报讲解自动跨页修复设计

## 背景

AI 动态汇报会按问题复杂度生成 1–12 个 HTML 页面，每个页面包含 2–4 个讲解分段。当前页面的全部分段自然播放结束后，讲解应切换到下一张有效页面并从其第一段继续。实际故障不绑定某个固定页码：有时第一页能切到第二页但第二页无法切到第三页，有时可以继续到第三页却无法切到第四页，并会从当前页第一段重新讲解。这说明任意一次后续推进都可能重新进入当前页面。

## 根因

播放游标使用 `finalReplacementFor` 解析后的最终有效页面 ID，跨页查找 `nextNarrationItem` 却直接在原始目录中按该 ID 查找。找不到时 `findIndex` 返回 `-1`，随后 `slice(itemIndex + 1)` 等价于从目录开头扫描。目录项再次解析为当前有效页面时，控制器会从当前页第一段重新播放，形成循环。

现有测试覆盖了同页分段推进、生成中页面等待和失败页面跳过，但没有覆盖动态页数报告从第一页连续推进到最终页的完整行为。局部的单次跨页测试无法发现第三次或更晚的回环。

## 目标行为

- 同一页面内仍按顺序播放 2–4 个讲解分段。
- 当前页最后一段自然结束后，只能进入严格位于当前页之后的有效页面。
- 报告页数为动态的 1–12 页；流程不得假设总页数为 3 页或 4 页。
- 每一次推进都必须使用最新的页面和目录快照重新计算规范化顺序，不能依赖自动播放开始时捕获的旧数组或旧索引。
- 下一页已就绪时，画布切换到下一页，并从下一页第一段开始讲解。
- 下一页仍在生成时，保持当前画布并显示等待状态；页面就绪后继续跨页。
- 失败页面继续被跳过。
- 替换页或更正页按最终有效页面去重，不得重新解析回当前页。
- 最后一张有效页面播放完成后进入“讲解已完成”，不得循环。
- 暂停、停止、手动跳页、追问打断与恢复行为保持不变。

## 方案

在讲解控制器中建立规范化的页面推进顺序：每次 `advance` 都从 `inputRef.current` 读取最新快照，按目录顺序解析每个目录项对应的最终有效页面，过滤失败项，并按最终页面 ID 去重。查找下一项时，先定位当前最终页面在该规范化顺序中的位置，再只扫描其后的候选项。规范化队列不能在自动播放开始时缓存为固定长度。

候选项处理规则：

1. 已就绪且存在有效讲解分段：选择页面、持久化新游标并播放第一段。
2. 计划中或生成中：记录等待的目录项，保持当前画布，待状态更新后重新解析。
3. 失败、无效、被同一最终页面去重：跳过并继续向后扫描。
4. 没有后续候选项：将讲解状态设为完成。

在开始下一页前增加最后两道不变量保护：解析出的下一页 ID 必须与当前最终页面 ID 不同，而且它在本次最新规范化顺序中的位置必须严格大于当前位置。每次自然结束只能提交一次推进；旧播放器、旧快照或已完成页面产生的迟到回调不得再次启动讲解。该保护用于阻止异常目录、替换关系或任意次数跨页后的状态更新再次造成自循环。

## 备选方案与取舍

- 仅增加 `nextSlide.id !== currentSlide.id` 判断：改动最小，但不能正确处理替换链、生成中页面和重复目录映射。
- 重写完整讲解状态机：边界最清晰，但超出本次小问题的必要范围，且会扩大暂停、追问和语音仲裁的回归风险。

因此采用规范化推进顺序，并保留现有控制器结构。

## 测试设计

先增加失败的回归测试，再修改生产代码：

- 控制器参数化测试：分别使用 1、2、5、12 张页面，每页配置 2–4 个分段，逐一结束所有播放器，断言页面 ID 始终单调前进并最终进入 `completed`。
- 循环回归测试：目录 ID 与当前最终页 ID 不一致或任意一次跨页已经更新游标时，不得重新请求或播放任一已完成页面的第一段。
- 完成测试：最后一张有效页结束后状态为 `completed`，播放器数量不再增加。
- 等待和失败页测试：保留并运行现有生成等待、失败跳过、暂停与追问恢复用例。
- 浏览器测试：使用超过 4 页的动态报告，逐一触发全部音频结束，逐跳断言画布显示对应下一页，最终显示讲解完成，并断言每页第一段语音在自动流程中只启动一次。

## 修改范围

预计只修改：

- `src/features/ai/report/useNarrationController.ts`
- `src/tests/narration-controller.test.tsx`
- 一个现有 Playwright 汇报场景文件

不修改服务端页面生成、TTS 网关、语音识别、唤醒词及用户当前进行中的 SSE 恢复改动。

## 验收标准

- 任意 1–12 页报告都能从第一页连续讲解到动态最后一页；单页报告直接完成，多页报告不在任何中间页停止或回环。
- 任一页面的第一段在一次连续播放流程中最多启动一次，除非用户明确选择“重播本页”或手动跳回该页。
- 页面切换和新页面第一段播放属于同一次自动推进，不出现旧页面重播间隙。
- 最后一页结束后稳定停留在完成状态。
- 新增回归测试、相关前端单元测试、浏览器测试和生产构建通过。
